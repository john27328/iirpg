# IIRPG — общая очередь сообщений

Начальный прототип текстовой RPG: два экземпляра одного класса `Chat`
публикуют сообщения в общей очереди и независимо читают доступные им записи.
Они показаны в одном окне браузера; ввод ручной с обеих сторон.
Сервер и история находятся на машине, где запущен Python.

## Запуск

Нужен Python 3.11+. У приложения нет внешних зависимостей.

```bash
PYTHONPATH=src python3 -m iirpg --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. Ссылка на диалог содержит идентификатор
комнаты после `#room=`; её можно скопировать кнопкой в интерфейсе. Открыв эту
ссылку в другом окне, вы увидите тот же диалог. Кнопка `+` создаёт новую комнату.
Сообщения обновляются через короткие HTTP-запросы.

В каждой форме можно выбрать видимость: «Обоим чатам» или «Только этому чату».
Сервер фильтрует записи до отправки клиенту. Чтение сообщения одним чатом
не удаляет его из очереди для остальных.

SQLite хранит историю в `.local/chat.sqlite3`; этот каталог исключён из Git.
История доступна после перезапуска с тем же файлом базы. Другой путь:

```bash
PYTHONPATH=src python3 -m iirpg --database .local/another.sqlite3
```

## Быстрые тесты

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тесты проверяют независимое чтение, серверную фильтрацию видимости, продвижение
курсора через скрытые записи, изоляцию комнат, восстановление и миграцию истории,
параллельные повторы без дублей и реальные HTTP-запросы.

Это основной набор для разработки: сейчас 18 тестов, обычно около секунды.
Покрываем поведение кода вне ИИ API и найденные регрессии, без квоты покрытия
и тестов на каждую внутреннюю функцию. Набор использует временные базы
и локальные HTTP-порты; внешние сервисы, ключи ИИ и работающий стенд не нужны.
Будущие ИИ-интеграции в этих тестах заменяем управляемыми заглушками.

## Релизные тесты

```bash
PYTHONPATH=src python3 -m unittest discover -s release_tests -v
```

Этот набор запускается отдельно перед релизом или при изменении запуска,
хранения и других затронутых механизмов. Первая проверка запускает настоящий
процесс сервера, перезапускает его с той же временной базой и проверяет историю,
видимость, защиту от дублей и необходимость ключа доступа. Рабочая база не меняется.
По мере необходимости сюда добавляются более длительные сквозные проверки.
Платные обращения к ИИ и оценки ответов модели должны запускаться отдельно
и только явно; обычные и релизные тесты их не вызывают.

## Структура

- `domain.py`: классы `Chat`, `Message`, `Visibility` и проверка сообщений.
- `application.py`: публикация в очередь и фильтрация по чату-подписчику.
- `storage.py`: единый журнал JSON-записей в SQLite и защита от дублей.
- `server.py`: HTTP API и раздача интерфейса.
- `web/`: HTML, CSS и один JavaScript-класс `Chat`, созданный дважды.
- [docs/message-queue.md](docs/message-queue.md): формат записей, видимость и API.

JSON задаёт формат сообщения. SQLite обеспечивает атомарность записи и порядок
при параллельных запросах. Старая история автоматически переносится в очередь
при первом запуске обновлённого сервера; идентификаторы и комнаты сохраняются.
Исходная таблица `messages` остаётся в базе как архив, новые записи идут в `queue_events`.

## Доступ извне

Для внешнего доступа запускайте сервер с ключом. Создать ключ один раз:

```bash
mkdir -p .local
python3 -c 'import os, secrets; fd = os.open(".local/access-token", os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600); os.write(fd, secrets.token_urlsafe(32).encode()); os.close(fd)'
PYTHONPATH=src python3 -m iirpg --access-token-file .local/access-token
```

После этого направьте Cloudflare Quick Tunnel на локальный сервер:

```bash
cloudflared tunnel --url http://127.0.0.1:8000
```

Команда напечатает HTTPS-ссылку. Откройте её и введите ключ, либо добавьте
к ней `#access=ВАШ_КЛЮЧ`. После входа кнопка копирования включает ключ в ссылку.
API проверяет ключ при каждом запросе; фрагмент URL не отправляется серверу
при загрузке страницы. Не публикуйте ключ в Git или общедоступных местах.

Сервер продолжает работать на этой машине;
туннель пересылает запросы. Ссылка действует, пока работает процесс туннеля,
и меняется при его перезапуске. Это демонстрационный сервер; любой обладатель
секретной ссылки получает доступ к чатам этого сервера.
Сейчас это общий административный стенд: обладатель ключа может открыть оба
представления. Выбор `chat` фильтрует ленту, но не удостоверяет личность пользователя;
раздельные права пользователей потребуют привязки подписчика к его авторизации.

При запуске в этой рабочей среде сервер и туннель оставлены в отдельных
tmux-сессиях. Посмотреть состояние:

```bash
tmux -L iirpg list-sessions
```

Логи находятся в `.local/server.log` и `.local/tunnel.log`, текущий адрес
туннеля — в `.local/public-url`, ключ — в `.local/access-token`.
Для остановки соответствующего процесса:

```bash
tmux -L iirpg send-keys -t tunnel C-c
tmux -L iirpg send-keys -t chat C-c
```

## Правила игры

Прототип пока не содержит материалов Pathfinder и не реализует игровые механики.
При их добавлении соблюдаем применимую ORC/OGL и сохраняем необходимые уведомления
и атрибуцию источников. Весь исходный код и распространяемый контент публичны.
