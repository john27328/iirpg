# IIRPG — общая очередь сообщений

Начальный прототип текстовой RPG: обычный чат `first` и тестовая JSON-заглушка
`second` публикуют сообщения в общей очереди и независимо читают доступные записи.
Интерфейс разделён на две страницы. `/` — тестовая игровая страница с чатом,
костями, персонажами и инвентарём. `/debug` — отладка: внутренние сущности,
JSON-заглушка с командами ведущего и полный лог чата. Переходы «Игра» / «Отладка»
сохраняют комнату и ключ доступа в ссылке; страницы можно открыть рядом
в разных окнах. Сервер и история находятся на машине, где запущен Python.

Во вкладке «Персонажи и инвентарь» ведётся реестр игроков и NPC комнаты.
Создавайте игроков-владельцев, привязывайте к ним персонажей, добавляйте предметы
из шаблонов или вручную, меняйте количество, хват и расположение: в руках,
на себе или убрано. Для NPC доступен тот же инвентарь. Данные сохраняются в SQLite.
Расчёт нагрузки Bulk, занятых рук и ограничений экипировки основан на Pathfinder
2e Remaster; перегруз отмечается, превышение максимума отклоняется.
Первый конфиг рассчитан на маленьких и средних существ.

Кнопка «Лист персонажа» открывает окно с шестью характеристиками, здоровьем,
КБ, спасбросками, восприятием, навыками и описанием. Для игроков показатели
считаются по уровню, характеристикам и владению; для NPC по умолчанию вводятся
итоговые значения блока характеристик. NPC также может использовать профиль
игрового персонажа. Сила общая для листа и инвентаря.
Здоровье и параметры брони пока заполняются вручную; классовые способности,
экипировка и состояния автоматически не добавляют поправки к листу.

В разделе «Мировоззрение и убеждения» задаются принципы и табу (edicts/anathema).
Их можно оставить пустыми. Это вариант PF2e Remaster, где классические девять
мировоззрений больше не используются. Для старых комнат предусмотрено
явное обновление снимка конфигурации — команда описана в документации листа.

Поля, разделы, профили, ограничения и формулы задаёт
`src/iirpg/rules/character_pf2e.json`. Другой конфиг:

```bash
PYTHONPATH=src python3 -m iirpg --character-rules path/to/character.json
```

Правила листа сохраняются отдельным снимком комнаты; старые персонажи
получают недостающие поля, сохраняя ID и инвентарь.
Модель, формулы и границы реализации — в [docs/character-sheet.md](docs/character-sheet.md).

Атрибуты, состояния, категории, лимиты и шаблоны задаёт
`src/iirpg/rules/inventory_pf2e.json`. Другой конфиг:

```bash
PYTHONPATH=src python3 -m iirpg --inventory-rules path/to/inventory.json
```

Комната сохраняет снимок правил при первом открытии реестра. Смена файла
влияет на комнаты, реестр которых ещё не открывали. Механика, ограничения,
происхождение правил и HTTP API описаны в [docs/inventory.md](docs/inventory.md).

## Запуск

Нужен Python 3.11+. У приложения нет внешних зависимостей.

```bash
PYTHONPATH=src python3 -m iirpg --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. Ссылка на диалог содержит идентификатор
комнаты после `#room=`; её можно скопировать кнопкой в интерфейсе. Открыв эту
ссылку в другом окне, вы увидите тот же диалог. Кнопка `+` создаёт новую комнату.
Сообщения обновляются через короткие HTTP-запросы.

В чате можно выбрать видимость: «Общее сообщение» или «Только игроку».
Сервер фильтрует записи до отправки клиенту. Чтение сообщения одним чатом
не удаляет его из очереди для остальных.

## JSON-заглушка

JSON-заглушка находится на странице `/debug`. На игровой странице ответы
`second` подписаны «Ведущий»; ведущего пока заменяют ручные команды заглушки.

Входящие записи показываются целиком как JSON, включая видимость и metadata.
По умолчанию редактор принимает короткие команды ведущего без служебных UUID:

```json
{"action": "offer_roll", "text": "Проверь скрытность.", "roll": "1d20+5", "target": 15}
```

Доступны `say`, `offer_roll`, `roll`. Для простого сообщения хватит `{"text": "Привет"}`.
Автор и получатель определены сервером; служебный ID автоматически передаётся
клиентом в заголовке. Повтор текущей команды безопасен. Кнопка «Новая отправка»
позволяет намеренно выполнить такую же команду снова, не редактируя JSON.
Видимость задаётся необязательным `audience`: `all`, `player` или `gm`.
Формат для ИИ: [docs/gm-commands.md](docs/gm-commands.md).

Инспектор отладки показывает комнату, игроков, PC/NPC, предметы с владельцами,
снимок правил, подписчиков и схемы инструментов в JSON. Полный журнал под ним
включает все события комнаты, в том числе скрытые от одного из подписчиков;
можно искать по тексту и UUID, фильтровать тип события и представление подписчика,
раскрывать исходный JSON. Список загружает историю порциями и получает новые события.
Собственная лента JSON-заглушки по-прежнему показывает только выборку `second`.
Отладка использует общий ключ административного стенда. Это разделение
интерфейса, а не отдельные пользовательские права.
Контракт инспектора: [docs/debug.md](docs/debug.md).

Для отладки доступен режим «Сырой JSON очереди». В нём меняйте `text`, `sender`,
`visibility` и `metadata`: тело запроса передаётся без автоматической подстановки полей.
Пробелы и переносы строк внутри `text` сохраняются. Сервер по-прежнему
проверяет формат сообщения и ограничения очереди.

После отправки JSON остаётся в редакторе. В сыром режиме повтор с тем же `request_id`
возвращает исходную запись. Для новой записи нажмите «Новый request_id»;
эта кнопка меняет только идентификатор. Неверный JSON или ошибка API
показываются рядом с редактором; введённый текст сохраняется.

### Варианты ответа

Необязательное поле `choices` задаёт кнопки под входящим сообщением в чате:

```json
{
  "sender": "second",
  "request_id": "2269de71-e2e6-4685-9872-b7739fa18e7d",
  "text": "Перед вами закрытая дверь. Что будете делать?",
  "choices": ["Осмотреться", "Открыть дверь", "Уйти"]
}
```

Нажатие сразу отправляет выбранный вариант. Собственный ответ можно написать
и отправить через поле ввода; уже набранный черновик сохраняется при выборе варианта.
Допускается до 10 непустых строк по 200 символов; `choices: []` убирает варианты.
В примере JSON-заглушки варианты уже заполнены. Для нового сообщения нужен новый
`request_id`, в том числе если изменён только список вариантов.

## Кости

Ведущий может предложить игроку проверку, не бросая кости за него.
В JSON-заглушке нажмите «Предложить бросок», затем «Отправить JSON».
В чате появятся описание, формула, условие успеха и кнопка «Бросить кости».
После нажатия результат появится в той же карточке. Повторное нажатие,
другое окно и перезагрузка страницы не перебрасывают выполненную проверку.
Для новой проверки нужно новое предложение с новым `request_id`.

Откройте панель «🎲 Кости» в чате: выберите формат, формулу и условие успеха,
затем нажмите «Бросить кости». В истории появятся запрос с формулой и условием,
затем ответ с отдельными значениями, итогом и успехом или неудачей.
Чат объединяет их в компактную карточку с автором броска, формулой, итогом
и статусом; отдельные значения костей раскрываются через «Подробности».
JSON-заглушка показывает обе записи целиком.
Собственный текстовый черновик сохранится.
Текущая настройка видимости применяется и к результату броска.

В JSON-заглушке кнопка «Пример костей» создаёт вызов `dice.roll`.
Так можно вручную отправить сырой запрос от будущего ИИ-ведущего (`second`),
без подключения модели. В JSON-истории видны `tool.call` и `tool.result`;
`tool_call_id` ответа ссылается на `request_id` вызова.
Повторная отправка с тем же `request_id` возвращает прежний бросок без новых записей.
Для нового броска нажмите «Новый request_id».

Форматы хранятся в `src/iirpg/rules/dice_systems.json`, отдельно от движка.
Поддерживаются сумма костей и подсчёт успехов в пуле; готовы примеры d20,
2d6, d100 и пула d10. Специальные правила выбранных игровых редакций будут
добавляться через стратегии и конфигурацию правил.
Контракт для будущего ИИ-ведущего: [docs/dice-tool.md](docs/dice-tool.md).

SQLite хранит историю в `.local/chat.sqlite3`; этот каталог исключён из Git.
История доступна после перезапуска с тем же файлом базы. Другой путь:

```bash
PYTHONPATH=src python3 -m iirpg --database .local/another.sqlite3
```

## Быстрые тесты

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тесты проверяют независимое чтение, серверную фильтрацию видимости, продвижение
курсора через скрытые записи, изоляцию комнат, восстановление и миграцию истории,
параллельные повторы без дублей и реальные HTTP-запросы.

Это основной набор для разработки: обычно выполняется за несколько секунд.
Покрываем поведение кода вне ИИ API и найденные регрессии, без квоты покрытия
и тестов на каждую внутреннюю функцию. Набор использует временные базы
и локальные HTTP-порты; внешние сервисы, ключи ИИ и работающий стенд не нужны.
Будущие ИИ-интеграции в этих тестах заменяем управляемыми заглушками.

## Релизные тесты

```bash
PYTHONPATH=src python3 -m unittest discover -s release_tests -v
```

Этот набор запускается отдельно перед релизом или при изменении запуска,
хранения и других затронутых механизмов. Первая проверка запускает настоящий
процесс сервера, перезапускает его с той же временной базой и проверяет историю,
видимость, защиту от дублей и необходимость ключа доступа. Рабочая база не меняется.
Проверяется и сохранённый результат костей: повтор после перезапуска не перебрасывает их.
По мере необходимости сюда добавляются более длительные сквозные проверки.
Платные обращения к ИИ и оценки ответов модели должны запускаться отдельно
и только явно; обычные и релизные тесты их не вызывают.

## Структура

- `domain.py`: классы `Chat`, `Message`, `Visibility` и проверка сообщений.
- `application.py`: публикация в очередь и фильтрация по чату-подписчику.
- `storage.py`: единый журнал JSON-записей в SQLite и защита от дублей.
- `dice.py` и `rules/dice_systems.json`: универсальный движок и форматы бросков.
- `roster.py`, `roster_storage.py`, `rules/inventory_pf2e.json`: игроки, персонажи,
  инвентарь, правила экипировки и хранение с защитой от конфликтов и повторов.
- `character_sheet.py`, `rules/character_pf2e.json`, `web/character-sheet.js`:
  конфигурируемые листы, профили игроков и NPC, формулы и окно персонажа.
- `server.py`: HTTP API и раздача интерфейса.
- `web/`: HTML, CSS, обычный `Chat` и тестовая `JsonStub` с сырым JSON-вводом.
- [docs/message-queue.md](docs/message-queue.md): формат записей, видимость и API.

JSON задаёт формат сообщения. SQLite обеспечивает атомарность записи и порядок
при параллельных запросах. Старая история автоматически переносится в очередь
при первом запуске обновлённого сервера; идентификаторы и комнаты сохраняются.
Исходная таблица `messages` остаётся в базе как архив, новые записи идут в `queue_events`.

## Доступ извне

Для внешнего доступа запускайте сервер с ключом. Создать ключ один раз:

```bash
mkdir -p .local
python3 -c 'import os, secrets; fd = os.open(".local/access-token", os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600); os.write(fd, secrets.token_urlsafe(32).encode()); os.close(fd)'
PYTHONPATH=src python3 -m iirpg --access-token-file .local/access-token
```

Откройте публичный адрес приложения и введите ключ, либо добавьте
к адресу `#access=ВАШ_КЛЮЧ`. После входа кнопка копирования включает ключ в ссылку.
API проверяет ключ при каждом запросе; фрагмент URL не отправляется серверу
при загрузке страницы. Не публикуйте ключ в Git или общедоступных местах.

### Прямой доступ по статическому IP

Основной способ — `https://ВАШ_ПУБЛИЧНЫЙ_IP/` через Caddy на этой же машине.
Python слушает `127.0.0.1:8000`; Caddy принимает HTTPS и обновляет сертификат для IP.
Установка и обслуживание: [docs/direct-ip.md](docs/direct-ip.md).
Домен и туннель для прямого доступа не нужны.
Ключ доступа и формат фрагмента `#room=…&access=…` сохраняются.

Для прямого HTTP-доступа по `http://ВАШ_ПУБЛИЧНЫЙ_IP:8000/`:

```bash
PYTHONPATH=src python3 -m iirpg --host 0.0.0.0 --port 8000 --access-token-file .local/access-token
```

Порт TCP 8000 должен быть открыт в firewall машины и провайдера.
По HTTP ключ доступа и сообщения передаются без шифрования.
Генерация ID работает без HTTPS через `crypto.getRandomValues()`;
если автокопирование ссылки недоступно, интерфейс показывает адрес для ручного копирования.

### Временный доступ через туннель

Если нужен временный адрес для разработки, можно запустить:

```bash
cloudflared tunnel --url http://127.0.0.1:8000
```

Сервер продолжает работать на этой машине;
туннель пересылает запросы. Ссылка действует, пока работает процесс туннеля,
и меняется при его перезапуске. Это демонстрационный сервер; любой обладатель
секретной ссылки получает доступ к чатам этого сервера.
Сейчас это общий административный стенд: обладатель ключа может открыть оба
представления. Выбор `chat` фильтрует ленту, но не удостоверяет личность пользователя;
раздельные права пользователей потребуют привязки подписчика к его авторизации.

### Состояние работающего стенда

Стенд использует прямой HTTPS по IP; туннель остановлен.
Python работает в tmux-сессии `chat`, Caddy — в systemd-службе `iirpg-caddy`.
Посмотреть состояние:

```bash
tmux -L iirpg list-sessions
systemctl status iirpg-caddy.service
```

Лог Python находится в `.local/server.log`, журнал Caddy доступен через
`journalctl -u iirpg-caddy.service`. Текущий публичный адрес — в `.local/public-url`,
ключ — в `.local/access-token`. Для остановки Python:

```bash
tmux -L iirpg send-keys -t chat C-c
```

## Правила игры

В [data/pathfinder2e-remaster](data/pathfinder2e-remaster/README.md) хранится
локальный английский справочник базовых правил PF2e Remaster: игровые проверки,
бой, навыки, состояния, создание персонажа, снаряжение, общие правила магии и DC.
25 текстовых файлов вместе с полной лицензией и атрибуцией занимают меньше 1 МиБ.
Для каждого документа сохранены источник, страницы, дата и SHA-256.
Тексты распространяются по ORC отдельно от кода; подробности — в
[ORC-NOTICE.md](data/pathfinder2e-remaster/ORC-NOTICE.md).

Движок костей пока использует общие форматы бросков; загрузка справочника
в контекст ИИ и реализация конкретных механик Remaster выполняются отдельно.
Весь исходный код и распространяемый контент публичны.

## Учебный бой

На экране боя `/battle` выберите Радана
и нажмите «Начать бой». Доступны удар мечом, поднятие щита, конец хода и ход
противника. Инициатива, действия, MAP, степени успеха, критический урон и ОЗ
считаются сервером; результаты появляются в чате и отладочном журнале.
Учебные ОЗ сохраняются отдельно от листа. При 0 ОЗ участник выбывает.
Это профиль спарринга; на загруженной карте используются позиции и укрытие.
Реакции, магия и dying/wounded пока не реализованы;
[границы и API](docs/character-sheet.md#учебный-бой).

## Сцена и действия

На игровой странице панель «Сцена и действия» позволяет добавить персонажа
из реестра, перемещаться по зонам, взаимодействовать с объектами и предложить
свободным текстом нестандартное действие. Ведущий выбирает поддержанный эффект
и при необходимости КС; изменения видны в сцене и журнале `scene.action`.
Пример: войти в зал → предложить опрокинуть стол → разрешить проверку → занять
укрытие. Состояние сохраняется после перезагрузки. Это зональная основа для карты,
с интеграцией позиций, движения и укрытия в новый учебный бой.
[Контракт и ограничения](docs/scene.md).

На панели сцены теперь есть клеточная карта и две JSON-заготовки: таверна
и лесной лагерь. Перемещение — кликом по свободной клетке, выбор объекта — кликом
по его значку. Доступны скачивание заготовки и импорт файла или JSON от ИИ.
[Формат, схема и готовое задание для генерации](docs/maps.md).

В учебном бою на карте кликайте клетку для перемещения (одно действие), а
противника — для удара. Противник умеет подходить к герою. ОЗ листа сохраняются.

### Учебный противник с ИИ

На экране `/battle` доступна кнопка «Одно действие ИИ»; контексты и ответы
можно посмотреть в `/debug`.
Подготовлен OpenRouter: только бесплатные модели, по умолчанию
`nvidia/nemotron-3.5-super-vl:free`, режим рассуждений отключён для коротких команд.
Ключ сервера хранится в `.local/openrouter-key` (вне Git), читается без перезапуска.
Настройки модели, профиля NPC и лимитов — `src/iirpg/rules/ai.json`;
альтернативные пути: `--openrouter-key-file PATH`, `--ai-config PATH`.
Без ключа внешних обращений нет. Контекст, ответы и результаты видны в `/debug`.
[Настройка и контракт ИИ](docs/ai.md).

В новом бою можно выбрать одиночного противника, патруль из двух или группу
из трёх. У каждого своя инициатива и цель удара. Контекст ИИ содержит личные
наблюдения, последствия команд и текущую задачу. Короткие доклады слышны только
поблизости; приказ может устареть, раненый NPC может отойти или сдаться.
[Контракт группового боя и ограничения](docs/group-combat.md).

## Отдельный экран боя

`/battle` объединяет карту, очередь инициативы, текущего героя и его игрока,
кнопки действий, текстовый ввод и журнал. Можно выбрать от одного до четырёх
героев комнаты; панель управления следует очереди, а черновик привязан к автору.
Знакомые текстовые команды исполняются движком; свободные описания ждут
решения ведущего. Ссылки между игрой, боем и отладкой сохраняют комнату и ключ.
[Экран, текстовые действия и API группы](docs/battle-screen.md).

На экране боя также есть выбор заготовки: дуэль в таверне, лесной патруль
или группа в таверне. Заготовка загружает карту и начинает бой одной
операцией; режим своей сцены сохраняет текущую карту. Каталог задаётся в
`src/iirpg/rules/battle_presets.json`.
