# Первые бои с ИИ

[Результаты первого живого прогона](ai-evaluation-2026-10-29.md).

ИИ подключён только к решениям учебного противника. Мастер и долгосрочная
память пока не реализованы. Механика, броски, ОЗ, доступность действий и
сохранение остаются на сервере. Один клик — одно решение модели; фонового
автозапуска, платных моделей и автоматических повторов нет.

## Ключ и конфигурация

На сервере создайте `.local/openrouter-key` с одним ключом OpenRouter,
без кавычек. Файл и каталог `.local/` исключены из Git. Ограничьте доступ:

```bash
chmod 600 .local/openrouter-key
```

Путь по умолчанию считается от рабочего каталога сервера. Для другого пути
есть `--openrouter-key-file /absolute/path`. Альтернатива — переменная
окружения `OPENROUTER_API_KEY`, она имеет приоритет. Ключ читается заново
при каждом запросе: после заполнения файла перезапуск не нужен. Он не
передаётся браузеру, не попадает в URL, промпт, SQLite и диагностику.

Обычный запуск из корня проекта:

```bash
PYTHONPATH=src python3 -m iirpg --host 127.0.0.1 --port 8000 --access-token-file .local/access-token
```

Общий ключ доступа к игре и ключ OpenRouter — разные файлы.

Настройки — `src/iirpg/rules/ai.json`, другой файл: `--ai-config PATH`.
Профиль NPC содержит `personality` и `goal`. По умолчанию:

- `model: "nvidia/nemotron-3.5-super-vl:free"` — закреплённая бесплатная модель;
- `reasoning: false` — короткий ответ с выбором команды без режима рассуждений;
- `max_tokens: 256`, таймаут 45 секунд;
- локальный лимит 100 попыток за сутки UTC на весь сервер, сохраняемый в SQLite;
- бюджет контекста 14000 байт JSON (это не точный подсчёт токенов).

Можно закрепить конкретную модель с суффиксом `:free`. Платные ID и
`openrouter/auto` отклоняются. В запросе дополнительно устанавливается
`provider.max_price: {prompt: 0, completion: 0}`. Платной запасной модели нет.
Настройки загружаются при старте; после их изменения нужен перезапуск.
Можно также поставить `openrouter/free` для автоматического выбора бесплатной
модели. Для сравнения результатов лучше оставлять конкретный ID.
Фактическая выбранная маршрутизатором модель сохраняется в ответе диагностики.

Используется [Chat Completions API OpenRouter](https://openrouter.ai/docs/api/reference/overview)
и [JSON Schema для ответа](https://openrouter.ai/docs/guides/features/structured-outputs).
Требуется провайдер, поддерживающий параметры запроса. Если среди бесплатных
провайдеров такого нет, запрос завершится ошибкой. Доступность и квоты
бесплатных моделей определяются OpenRouter. Запросы передают учебный контекст
выбранному внешнему провайдеру; в нём нет секретных заметок мастера или чата.

## Проверка в интерфейсе

1. Подготовьте карту на странице игры, затем перейдите в `/battle`, выберите
   героев с ОЗ и группу противников и начните бой.
2. Дождитесь хода противника: при необходимости закончите ход героя.
3. Ссылка на отладку ведёт к запросам и ответам NPC. Для предварительного
   просмотра без вызова модели есть `GET /api/rooms/{room}/ai/npc/context`.
4. Нажмите «Одно действие ИИ». Повторяйте до конца хода либо используйте
   кнопку «Весь ход · обычная тактика» для сравнения с обычным алгоритмом.
5. В `/debug` выберите «ИИ · контексты, запросы и ответы». Там последние
   20 запросов комнаты: точный промпт, JSON Schema, ответ, модель, usage,
   время выполнения, выбранная команда, результат или ошибка.

Если действия закончились, экран предлагает закончить ход NPC без запроса
модели. Прямой API ИИ по-прежнему допускает выбор конца хода. Локальный и провайдерский лимиты учитывают неудачные попытки.
При 429, ошибке формата или сетевой ошибке бой не меняется. Следующий клик
после окончательной ошибки создаёт новую попытку явно. После обрыва браузерного
соединения «Проверить результат запроса» повторяет тот же ID без нового обращения к модели.
При перезагрузке страницы ID можно найти в диагностике; автоматически запрос
не возобновляется.

## Контекст и границы

`ai_context.py` строит контекст версии 2: `role: npc`,
`mode: local_observations`, `actor_id` активного участника. Мастер,
предложения действий, реестр персонажей и история чата в него не включаются.
Точные ОЗ, КБ, атака и ресурсы известны только о себе. О других передаются
видимые позиции, щит, укрытие и качественное состояние: fit, wounded,
badly_wounded, down, surrendered. Эффективная КБ противника неизвестна.

Контекст включает текущую задачу (`current_intent`), роль в группе,
последний услышанный приказ с возрастом, контакты со способом получения
сведений, шесть последних замеченных событий и собственные действия в этом
ходу. Нет общей всеведущей истории. Сохраняется краткая память столкновения;
долгосрочная память между встречами пока отсутствует.

Для каждой команды указаны последствия: стоимость, изменение КБ, потеря
укрытия, модификатор удара с текущим штрафом либо результат перемещения.
Варианты движения включают сближение одним действием, путь к укрытию,
отход и соседние клетки; максимум десять вариантов, проверенных на известном
состоянии. `priority_candidates` предлагает несколько вариантов под текущую
задачу, но не ограничивает выбор модели. Это помощь в оценке доступных действий,
а не дополнительный вызов модели или скрытый планировщик против игрока.

Модель выбирает один ID:

```json
{"choice":"shield"}
```

Доступны удар по конкретной видимой цели, щит, укрытие, движение и конец хода.
При тяжёлом собственном ранении, известной потере товарища или свежем приказе
об отходе также можно сдаться. Движение проверяется той же функцией, которой
исполняется в бою. Меню строится по наблюдениям: неожиданно занятая невидимым
участником клетка может привести к отказу сервера без расхода действия.

Зрение и слух — явный пространственный прототип, не полная система обнаружения
PF2e. Стены преграждают зрение; слух ограничен длиной пути по полу и общим
языком. Геометрия карты и объекты заранее известны. Темноты, скрытности,
проверок восприятия, дверей и тумана войны для браузера пока нет. Полный вид
карты и общий чат являются административным представлением; фильтрация
наблюдений применяется к запросам NPC. [Группы и координация](group-combat.md).

Модель не назначает урон, результаты бросков, ревизии и ID операций. Контекст
не считается источником истины: результат применяется только к исходной
ревизии боя. Если бой успел измениться, решение сохраняется как `stale`.

## Транспорт и восстановление

- `GET /api/ai` — модель, наличие ключа без его значения, дневной счётчик.
- `GET /api/rooms/{room}/ai/npc/context` — контекст текущего хода NPC без сети.
- `POST /api/rooms/{room}/ai/npc/step` — тело `{"revision": N}` и UUID
  `Idempotency-Key`. Никаких промптов, ключей или моделей в HTTP-теле клиента.

Все API защищены тем же доступом, что и игра. Перед обращением к модели
SQLite сохраняет запрос со статусом `running`. Сетевой вызов выполняется без
открытой транзакции игры; одновременно разрешён один новый запрос на сервере.
Ответ сохраняется как `chosen` перед исполнением команды. Для команды боя
используется стабильный производный UUID. Поэтому повтор запроса или сбой
между исполнением команды и записью ответа не тратит действия повторно.

Статусы: `running`, `chosen`, `completed`, `failed`, `stale`. Если процесс
оборвался после отправки модели, но до сохранения ответа, результат неизвестен:
автоматического повтора нет. Через 120 секунд можно явно сделать новый запрос.
Старый ID никогда не вызывает повторное обращение к модели. Сохранённый
`chosen` можно безопасно доисполнить тем же ID после перезапуска.

Обычные тесты используют заглушку клиента и не обращаются к внешним ИИ API.
Живой тест после добавления ключа выполняется вручную кнопкой в интерфейсе.
Для отдельной комнаты и отчёта есть явно запускаемый сценарий:

```bash
PYTHONPATH=src python3 release_tests/live_ai_combat.py --scenario tavern --group patrol --max-ai-requests 12
```

Сценарии: `tavern`, `forest`, `cover`; группы: `duel`, `patrol`, `squad`. Герой управляется обычным алгоритмом,
противник — моделью. Исчерпание действий завершает ход без запроса модели.
Отчёт по умолчанию `.local/live-ai-combat.json`: команды, время, usage, исход,
проверка сохранения ОЗ листа и синхронизации карты. Сценарий не входит в
автоматическое обнаружение unittest и делает настоящие внешние запросы.

Будущий локальный провайдер можно подключить к той же границе `ready/complete`;
интеграция Ollama и контекст мастера пока не реализованы.
