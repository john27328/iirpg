# Связанные зацепки в кампании — 25 ноября 2026

Новая локация теперь содержит исследуемое наблюдение, связанное с конкретным
местным объектом, и вопрос для дальнейшего поиска в другой главной точке.
Если игроки пришли по уже найденному следу, генератор обязан продолжить
хотя бы одну ведущую сюда зацепку. Локация получает роль в текущем поиске,
вместо набора независимых атмосферных деталей.

Это развитие слоя кампании, общее для её эпизодов. Старые сохранённые сцены
не пересоздаются и не получают задним числом новую историю.

## Как работает исследование

В ответе генератора появился массив `discoveries` из одной или двух записей:

| Поле | Назначение |
| --- | --- |
| `source` | Индекс реального объекта в `features` |
| `trigger` | `look` для осмотра или `open` для содержимого закрытого объекта |
| `observation` | Что можно обнаружить: надпись, отметку, след; не готовый приговор |
| `destination` | ID другой существующей главной точки региона |
| `question` | Конкретный вопрос для поиска в следующей точке |
| `follow_up` | ID уже найденной зацепки, ведущей в эту область, либо пустая строка |

Объект-источник не может быть выдуманным, повторяться в двух зацепках сцены
или требовать открытия, если он не является вскрываемым препятствием.
Продолжение может ссылаться только на найденную зацепку нужной области.
Модель не может переписать исходное наблюдение, изменить его автора или
поставить произвольному заданию флаг завершения.

След может привести обратно в уже созданную точку. Она сохраняет прежнее
описание; исследование нового участка её окрестностей создаёт отдельную
сцену с учётом текущего вопроса. Старую сцену для этого не пересоздают.

Посещение не открывает наблюдение. «Изучаю записку» выполняет обычный `look`
без броска. Для содержимого запертого ящика сначала требуется успешное
открытие. Подготовка броска и провал проверки не раскрывают содержимое.
Само структурированное скрытое наблюдение в контекст ответа до изучения
не попадает. Художественное описание может преждевременно раскрыть похожую
подробность — проверка полей не понимает весь смысл свободного текста.
Осмотр уже открытого объекта показывает его текущее состояние, видимые
предметы внутри и прежнюю находку. Исходное описание закрытого замка после
вскрытия не подставляется как совет снова его открыть; скрытые вложения при
перечислении содержимого не выдаются.

У открытой зацепки есть автор, время, исходное место и конкретный источник.
Если записку унесли и прочитали на площади, сохраняются и её происхождение,
и место прочтения. Повторный осмотр не меняет первого автора, не дублирует
находку и не сбрасывает продвижение.

Продвижение имеет три состояния:

1. Наблюдение найдено.
2. Место, куда оно ведёт, посещено.
3. Найдено новое наблюдение, продолжающее этот след.

Последнее означает, что след продолжен; оно не доказывает вину человека и
не завершает всю загадку. Продолжение может уточнить прежнюю версию или
поставить её под сомнение. Старое наблюдение остаётся доступным в исходном виде.

## Контекст и сохранение

Для генератора выбираются до шести найденных зацепок. Неисследованное
содержимое соседних объектов туда не добавляется. В первую очередь выбираются
активные следы, ведущие в создаваемую область, чтобы старые завершённые
ответвления не вытеснили причину прихода игроков.

В контексте ответа игроку используются имена героев, названия источников и
мест, наблюдение и понятное описание продвижения. Внутренние ID зацепок там
не нужны; генератор получает их отдельно для проверяемых связей. Перед
публикацией ответов известные ссылки на места, объекты и зацепки заменяются
их названиями. Структурированные ID в сохранениях и квитанциях остаются
прежними. Неизвестный технический текст и шаблонные реплики это не исправляет.

Находки хранятся в `world.leads`, а открытие источника — в изменениях его
сохранённой сцены. Работают прежние сжатые снимки и ветки кампании. Загрузка
точки до второй находки сохраняет первую и исключает её будущее продолжение.
Новых API, внешних библиотек и обязательных вызовов модели для записи находки
не добавлено: меняется существующее исполнение осмотра/открытия.

## Проверки

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 -m unittest discover -s release_tests -v
PYTHONPATH=src python3 release_tests/live_multiplayer.py --live --case campaign_investigation
```

Проходят 330 обычных тестов и 13 отдельно запускаемых проверок. Новые тесты
проверяют отсутствие наблюдения до осмотра, закрытый источник и провал,
разных авторов, чтение перенесённой записки, недопустимые ссылки, продолжение
заданного вопроса и восстановление ветки. Тысяча посторонних зацепок не
превращается в тысячу записей в запросе модели.

Процессный тест останавливает сервер перед броском второго героя по ящику
с продолжением. После запуска чужой доступ получает 403, собственный бросок
раскрывает продолжение, исходный автор первой находки сохраняется. Второй
перезапуск и повтор броска также сохраняют результат без дубликатов.

В первом живом прогоне Радан изучил остатки лагеря на берегу и нашёл
обгоревшую записку о грузе к закату. Лира пошла к парому и изучила мешок
с отметкой «К-7». Записались два разных автора и проверяемая связь источников.
Модель правильно назвала обоих, но показала технические ID; после этого
представление журнала для ответов игроку заменено на имена и названия,
а отображение известных ссылок дополнительно проверяется кодом. Два повтора
того же пути также прошли: в одном следующая сцена появилась в каменоломнях,
в другом след вернулся к знакомому берегу. Схема не привязана к названиям
этих конкретных источников или одному заранее заданному маршруту.

Расширенный прогон прошёл три источника: берег → паром → башня. Последнюю
зацепку Радан получил после успешного вскрытия замка. Нашлось противоречие
в повторном осмотре: исходное описание снова советовало открыть уже выломанный
замок. Исправлены выбор текущего описания и повторное чтение находки. Затем
открытый объект из этого настоящего прогона повторно осмотрен на отдельной
копии сохранения: состояние и прежние авторы остались неизменными, старый
совет про закрытый замок исчез.

В сумме четыре маршрута использовали 49 вызовов бесплатной модели; их 139
проверок состояния и протокола прошли. Точечный повторный осмотр потребовал
ещё два вызова. Заявленная стоимость всех вызовов — 0. Это не 139 независимых
оценок качества сюжета: речь и содержательность связей проверяются вручную.
Изолированные отчёты и базы находятся в `.local/nov25-investigation-*.json`
и `.sqlite3`; пользовательские игры не изменялись.

## Что ещё ограничено

Формальная схема пока покрывает физические источники; показания NPC не
выделены в отдельный тип свидетельства. Отдельных доверия источнику,
проверки достоверности слуха и окончательной процедуры разрешения загадки нет.
Модель сама пишет наблюдения: структурная проверка связывает их, но не
доказывает смысловую непротиворечивость всех текстов.

Генератор может по-прежнему написать слабую загадку, а ведущий — добавить
неподтверждённую реплику или сказать что-то за героя. Деньги, авторы, открытия
и продвижение этим текстом не меняются. Автоматические проверки оценивают
эти состояния; качество диалогов проверяется отдельно. Это шаг к большому
приключению, а не доказательство надёжности автономного многолетнего сюжета.
