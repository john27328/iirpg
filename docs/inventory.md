# Персонажи, игроки и инвентарь

В комнате есть отдельный реестр игроков (`players`), персонажей (`characters`)
и принадлежащих персонажам предметов (`inventory_items`). Игрок — запись владельца,
а не учётная запись для входа. Один игрок может иметь несколько персонажей.
`kind: pc` обозначает игрового персонажа с необязательным `player_id`, `kind: npc`
— NPC без игрока-владельца. Обе разновидности используют одинаковые правила
инвентаря. У персонажа есть имя, размер, атрибуты из конфига, количество монет
и заметки. У предмета — количество, категория, Bulk одного экземпляра,
расположение, хват, требования к рукам, заметки и необязательная ссылка на источник.

Реестр изолирован по комнатам, сохраняется в той же SQLite, что и история,
и доступен всем обладателям общего ключа стенда. Скрытых NPC и личных прав
пока нет; переключение фильтра в интерфейсе не ограничивает доступ.
Изменения реестра не создают сообщений в очереди чата.

## Конфигурация правил

По умолчанию используется `src/iirpg/rules/inventory_pf2e.json`:
Pathfinder Second Edition Remaster, Player Core (2023), pp. 267–271, 287.
Основа — [локальный справочник](../data/pathfinder2e-remaster/rules/equipment.md)
и [исходный раздел Equipment](https://2e.aonprd.com/Rules.aspx?ID=2143).
Механические данные конфига распространяются по ORC; уведомление и полная
лицензия входят также в устанавливаемый пакет Python.

Свой конфиг можно передать при запуске:

```bash
PYTHONPATH=src python3 -m iirpg --inventory-rules path/to/inventory.json
```

Конфиг определяет:

- `attributes`: ключи, названия, минимумы, максимумы и начальные значения атрибутов;
- `sizes`, `default_size`: поддержанные размеры и начальный размер;
- `hands`: количество рук;
- `states`, `default_state`, `worn_state`: состояния предметов, подписи и `uses_hands`;
- `categories`: категории, подписи, `worn_count_limit`, `worn_bulk_limit`
  и `carried_bulk_extra`;
- `bulk`: стратегию расчёта, число лёгких предметов и монет на Bulk,
  атрибут для нагрузки и базовые пороги;
- `catalog`: небольшие готовые шаблоны предметов; пользователь может описать свой;
- `source`, `source_url`, `license`, `notice`: происхождение правил.

`worn_bulk_limit` и `carried_bulk_extra` выражаются во внутренних лёгких единицах:
в комплектном конфиге 10 единиц = 1 Bulk. Категории без ограничения не имеют
искусственных слотов «голова», «ноги» и т. п. UI строит атрибуты, состояния,
категории и шаблоны из конфига комнаты.

Полный снимок конфига сохраняется в `room_rosters.rules` при первом открытии
реестра комнаты. Замена файла на сервере влияет на комнаты, реестр которых
ещё не открывали. Старые комнаты сохраняют свою механику. Перенос существующих
данных на другую механику потребует отдельной явной миграции.

Сейчас реализована одна стратегия расчёта — `pf2e`. Добавление механики с другой
математикой требует новой стратегии Python; числовые лимиты, атрибуты,
категории и состояния меняются JSON-конфигом. Неизвестная стратегия или
некорректный конфиг отклоняются при запуске.

## Реализованная часть Pathfinder

- Held / worn / stowed: в руках, на себе и убрано. В руках может быть предмет
  с хватом от одной руки до количества рук персонажа; стопку надо разделить
  на отдельные записи, чтобы взять один экземпляр.
- Удержание и готовность к использованию различаются. Двуручный предмет можно
  держать одной рукой. `required_hands: 1, free_hands: 1` моделирует требование
  `1+` у лука. Это проверка хвата, без расчёта атак и владения оружием.
- 10 лёгких предметов (`L`) = 1 Bulk. Остаток лёгких предметов игнорируется
  при сравнении с лимитами и показывается отдельно. `—` не добавляет Bulk.
- Монеты всех номиналов учитываются общим количеством: каждые 1000 = 1 Bulk,
  с отдельным округлением вниз. Денежные операции и стоимость не рассчитываются.
- Нагрузка сверх `5 + модификатор Силы` даёт отметку перегруза. UI поясняет
  clumsy 1 и −10 футов Скорости; сами характеристики боя ещё не рассчитываются.
  Изменение сверх `10 + модификатор Силы` отклоняется без записи.
- Bulk брони вводится для надетой брони. При переноске добавляется 1 Bulk;
  лёгкая броня при переноске считается 1 Bulk. Надет один комплект брони.
- На себе можно носить до 2 Bulk наборов инструментов для быстрого доступа.

Первый конфиг рассчитан на Small и Medium. Пересчёт размеров Tiny/Large/Huge,
контейнеры и скидка рюкзака, перенос существ, магическое инвестирование,
специальные слоты конкретных магических предметов, щиты с креплениями,
автоматические бонусы AC, боевые действия и их стоимость пока не реализованы.
«Убрано» обозначает недоступное сразу снаряжение без отдельной модели контейнера.
Предметы вводятся вручную или по четырём примерам Bulk Values из правил;
это не полный каталог предметов.

## HTTP API

`GET /api/rooms/{room_id}/roster` возвращает:

```json
{
  "revision": 0,
  "rules": {"id": "pf2e-remaster", "...": "полный снимок конфига"},
  "players": [],
  "characters": []
}
```

У каждого персонажа в ответе есть `items` и вычисленная `summary`:
`bulk`, `light_remainder`, `encumbered_at` (максимум без перегруза), `maximum`,
`encumbered`, `over_capacity`, `hands_used`, `hands_total`, `ready_item_ids`.

`POST /api/rooms/{room_id}/roster` принимает JSON и UUID в `Idempotency-Key`:

```json
{
  "action": "create_character",
  "revision": 0,
  "data": {"name": "Купец", "kind": "npc", "attributes": {"strength": 1}}
}
```

Ответ: `{"revision": 1, "entity_id": "UUID"}`. Новое состояние читается GET.
Следующая команда, например:

```json
{
  "action": "add_item",
  "revision": 1,
  "character_id": "UUID персонажа",
  "data": {
    "name": "Кинжал", "category": "weapon", "bulk": "L",
    "quantity": 1, "state": "held", "hands": 1, "required_hands": 1
  }
}
```

Команды: `create_player`, `update_player`, `delete_player`, `create_character`,
`update_character`, `delete_character`, `add_item`, `update_item`, `remove_item`.
`update_*` принимает частичные поля в `data`; запись задаётся через `id`.
Для предметов также обязателен `character_id`. Неизвестные поля `data` отклоняются.
При изменении состояния предмета без явного `hands` хват автоматически становится
одной рукой для held-состояния или нулём для остальных.

Каждая команда исполняется в одной транзакции с `BEGIN IMMEDIATE`. Проверка
`revision` предотвращает перезапись изменений из другого окна. Успешная команда
повышает ревизию на 1. Повтор с тем же ключом и телом возвращает исходную квитанцию,
в том числе после перезапуска и последующих изменений. Новое действие требует
нового UUID. Та же операция с другим телом или устаревшая ревизия дают HTTP 409.
Некорректные данные дают 400, чужая или отсутствующая запись — 404, отсутствие
ключа доступа защищённого сервера — 401. Ошибки не меняют ревизию и записи.

Удаление персонажа удаляет его инвентарь. Перед удалением игрока необходимо
отвязать его персонажей. Ограничения прототипа: 100 игроков, 200 персонажей,
500 записей инвентаря на персонажа в комнате. Это ограничения приложения,
а не правила игры.
