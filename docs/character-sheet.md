# Лист персонажа

На игровой странице откройте «Персонажи и инвентарь», выберите персонажа
и нажмите «Лист персонажа». Окно показывает характеристики, здоровье, защиту,
спасброски, восприятие, навыки, описание и краткую экипировку. «Редактировать»
открывает поля выбранного профиля; сохранение пересчитывает показатели на сервере.
Кнопка «К инвентарю» возвращает к инвентарю того же персонажа.

Игроки и NPC остаются одной сущностью `characters`. Владение игроком
(`player_id`), тип (`kind`), общий словарь `attributes` и инвентарь сохраняются.
Сила в листе и расчёте Bulk — одно значение. Отдельных копий характеристик,
отдельной базы NPC или второго инвентаря нет.

## Конфиг и модель

`src/iirpg/rules/character_pf2e.json` задаёт начальную реализацию Pathfinder
Second Edition Remaster. Другой конфиг передаётся при запуске:

```bash
PYTHONPATH=src python3 -m iirpg --character-rules path/to/character.json
```

Конфиг содержит:

- `attributes`: названия характеристик, минимумы, максимумы, начальные значения;
- `groups`: разделы листа и их подписи;
- `profiles`: поля, формулы, ограничения, описание и допустимые типы персонажей;
- `default_profiles`: начальный профиль для `pc` и `npc`;
- `help`: пояснение в окне листа;
- `source`, `source_url`, `license`, `notice`: источник и лицензирование механики.

Порядок разделов, полей, характеристик и показателей соответствует порядку
ключей в конфиге; при сохранении снимка этот порядок сохраняется.
Поле профиля бывает `integer`, `text` или `choice`. Значения проверяются
сервером по диапазонам, длинам и спискам вариантов из конфига. Неизвестные
поля отклоняются. UI строит форму и отображение показателей из этого же конфига.
`overview: false` оставляет поле в редакторе, скрывая его в обзоре: так исходные
поправки и ранги владения не дублируют рассчитанные модификаторы.
Характеристики листа объединяются с характеристиками инвентаря. При совпадении
ключа ограничения существующего инвентаря имеют приоритет — например, для Силы.

Сам движок в `character_sheet.py` не содержит названий характеристик,
скиллов, профилей Pathfinder или формулы владения. Он исполняет ограниченные
декларативные выражения, без `eval`, скриптов и доступа к Python:

```json
{"add": [10, {"ref": "attributes.dexterity"}, {"ref": "sheet.armor_other"}]}
```

Операции: `add`, `multiply`, `min`, `max`, `lookup`, `if_equal`.
`ref` обращается только к объявленным `attributes.KEY` или `sheet.KEY`.
`lookup` принимает выражение ключа и таблицу вариантов:

```json
{"lookup": [{"ref": "sheet.armor_rank"}, {"untrained": 0, "trained": 2, "expert": 4, "master": 6, "legendary": 8}]}
```

`if_equal` принимает сравниваемые значения и две ветви. Формулы проверяются
при загрузке: ссылки, типы, операции и глубина до 16 уровней. Ссылки на другие
вычисленные показатели не поддерживаются, циклы невозможны.
Ограничения профиля сейчас сравнивают два числовых выражения через `<=`.
В комплектном конфиге текущие ОЗ не могут превышать максимальные.

## Профили Pathfinder

Источники: локальный [Character Creation](../data/pathfinder2e-remaster/rules/character-creation.md),
[исходный Player Core](https://2e.aonprd.com/Rules.aspx?ID=2027),
[Building Creatures, GM Core](https://2e.aonprd.com/Rules.aspx?ID=2874).
Уведомление ORC находится в `src/iirpg/rules/character-ORC-NOTICE.md`,
полная лицензия уже включена в пакет. Каталоги классов и блоки конкретных
существ не копируются.

Профиль `pc` доступен игровым персонажам и NPC, построенным как игроки.
Уровень — от 1 до 20. Шесть характеристик — модификаторы, а не старые значения
характеристик 10/12/14. Владение задаётся отдельно для каждого показателя:
необучен = 0; обучен / эксперт / мастер / легенда = уровень + 2 / 4 / 6 / 8.

- Восприятие = Мудрость + владение + введённые поправки.
- Стойкость = Телосложение + владение + поправки; Рефлекс использует Ловкость,
  Воля — Мудрость.
- Каждый из 17 навыков использует указанную в правилах характеристику,
  владение и поправки. Для Lore предусмотрена одна область Знания.
- КБ = 10 + Ловкость с пределом брони + владение бронёй + бонус брони + поправки.
- КС класса = 10 + ключевая характеристика класса + владение КС + поправки.
- Очки героизма — от 0 до 3, начальное значение 1 при создании листа.
  Начало новой игровой сессии не отслеживается автоматически.

Профиль `npc` предназначен для готовых блоков характеристик. Уровень от −1
до 25, КБ, спасброски, восприятие и навыки вводятся итоговыми числами из блока.
Они не складываются с уровнем и характеристиками второй раз. У NPC нет полей
КС класса и очков героизма. При необходимости NPC можно выбрать профиль `pc`.
Смена профиля заменяет его специфические поля; общие поля можно передать заново.
Редактор сохраняет черновики обоих профилей до закрытия или сохранения окна.
При смене типа персонажа профиль должен быть совместим: перед преобразованием
NPC с профилем `npc` в игрового персонажа сначала переключите его на `pc`.

ОЗ, Скорость, происхождение, предыстория и класс вводятся вручную. Начальные
ОЗ равны нулю, пока лист не заполнен; Скорость по умолчанию 25 футов, её нужно
проверить по происхождению или блоку NPC. Состояние «при смерти» не выводится
из ОЗ автоматически. Временные ОЗ хранятся отдельно, расходование и урон
не автоматизированы. Способности, Удары, заклинания, чувства, языки, иммунитеты,
слабости и сопротивления пока текстовые.

Раздел «Мировоззрение и убеждения» содержит необязательные текстовые поля
«Принципы (эдикты)» и «Табу (анафема)» для обоих профилей. В Remaster
классические девять мировоззрений удалены; вместо них характер описывают,
в частности, через эти убеждения ([Paizo](https://paizo.com/blog/pathfinder-society-and-the-remaster),
[Player Core, p. 26](https://2e.aonprd.com/Rules.aspx?ID=2045)).
Принципы говорят, к чему персонаж стремится, табу — чего он старается не делать.
Для отдельных классов и религий возможны обязательные ограничения; их проверка
не автоматизирована. Пустые поля допустимы, описание можно менять по ходу игры.

Это лист учёта и базовый расчёт модификаторов. Автогенерация по классу и
происхождению, проверка доступности рангов и черт, автоматические бонусы
экипировки, штрафы брони, эффекты состояний, spellcasting и боевые действия
пока не реализованы. Эти поправки надо внести вручную в соответствующие поля.
Инвентарь отдельно показывает перегруз; clumsy 1 не применяется к КБ и навыкам
автоматически. Нельзя считать показанные результаты полным расчётом всех эффектов.

## Хранение и API

В `room_rosters` добавляется nullable-колонка `character_rules`. При первом
чтении комнаты обновлённым сервером туда записывается снимок текущего конфига
листа. Существующий снимок инвентаря сохраняется. Замена файла конфигурации
влияет только на комнаты без снимка листа. Перенос заполненных листов на другую
схему требует отдельной миграции.

Для существующих снимков без полей убеждений есть явное обновление:

```bash
PYTHONPATH=src python3 scripts/add_character_beliefs.py --database .local/chat.sqlite3
PYTHONPATH=src python3 scripts/add_character_beliefs.py --database .local/chat.sqlite3 --apply
```

Первый запуск только показывает число подходящих комнат. `--apply` создаёт
резервную копию SQLite рядом с базой и добавляет два поля и их раздел.
Можно ограничить обновление одной комнатой через `--room UUID`.
Характеристики, предметы, формулы и прежние настройки сохраняются;
ревизия обновлённой комнаты увеличивается на 1, чтобы старые формы получили
конфликт вместо перезаписи. Повтор не меняет уже обновлённые снимки.
Другие системы пропускаются; конфликт существующего определения поля
останавливает всю операцию без частичных обновлений. При следующем запуске
сервера новые комнаты получают обновлённый конфиг обычным способом.

Старые персонажи получают поля листа и недостающие характеристики с начальными
значениями при чтении. Их ID, владельцы, значения Силы, предметы и ревизия
сохраняются. Новые данные записываются в `characters.body` при следующей
успешной операции; чтение существующего реестра не повышает ревизию.

`GET /api/rooms/{room}/roster` дополнен `character_rules`. У каждого персонажа:

```json
{
  "attributes": {"strength": 3, "dexterity": 2, "constitution": 1, "intelligence": 0, "wisdom": 2, "charisma": 0},
  "sheet": {"profile": "pc", "values": {"level": 3, "hp_max": 25, "hp_current": 18, "…": "все нормализованные поля профиля"}},
  "sheet_statistics": {"armor_class": 12, "athletics": 3, "…": "рассчитанные значения"}
}
```

Изменение использует существующий `POST /api/rooms/{room}/roster`, `revision`
и UUID в `Idempotency-Key`:

```json
{
  "action": "update_character",
  "revision": 4,
  "id": "UUID персонажа",
  "data": {
    "attributes": {"strength": 4},
    "sheet": {"values": {"hp_current": 12, "athletics_rank": "trained"}}
  }
}
```

Максимальный размер тела HTTP-запроса — 64 KiB, чтобы заполненный лист
с многострочным описанием помещался в одну атомарную операцию.

Частичные обновления `attributes` и `sheet.values` сохраняют остальные значения.
При смене `sheet.profile` новый профиль получает переданные поля и начальные
значения остальных полей. Неизвестные поля, несовместимый профиль, неверные
типы или невозможное здоровье дают 400 без изменений. Изменение Силы также
проверяет максимальный Bulk. Устаревшая ревизия и повтор ID с другим телом
дают 409; повтор той же успешной операции возвращает исходную квитанцию.

В `/debug` отдельная группа «Правила листа персонажа» показывает снимок
конфига, а сущности персонажей включают поля листа и рассчитанные показатели.
Ключ доступа и границы комнат совпадают с существующим API реестра.

## Учебный бой

На игровой странице есть панель «Учебный бой PF2e»: выберите героя и начните
спарринг. Это отдельная сохраняемая симуляция: исходные ОЗ и инвентарь листа
не меняются. Профиль предполагает экспертное владение учебным мечом и ближнюю
дистанцию. Доступны удар, поднятие щита, конец хода и автоматическое исполнение
хода противника. При 0 ОЗ участник выбывает, победитель сохраняется.

`GET/POST /api/rooms/{room}/combat` использует общий ключ, ревизию и
`Idempotency-Key`. Действия: `start` (также `character_id`), `strike`, `shield`,
`end_turn`, `enemy_turn`. Результаты, состояние и записи очереди атомарны;
повтор возвращает прежний результат. Инициатива, четыре степени успеха,
натуральные 1/20, стандартный MAP, двойной урон крита и бонус поднятого щита
обрабатываются сервером. Снимок параметров — `rules/combat_pf2e.json`.

Это ещё не полный боевой движок: нет позиций, реакций, dying/wounded,
сопротивлений, состояний, заклинаний и проверки реального владения оружием.
Учебный профиль подходит для созданного воина Радана. Числа и результаты
событий доступны в чате и полном журнале отладки.
