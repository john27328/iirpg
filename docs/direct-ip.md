# Прямой доступ по статическому IP

Туннель и доменное имя для прямого доступа не требуются.
Доступны HTTP напрямую к Python и HTTPS через Caddy на этой же машине.
История SQLite и проверка ключа остаются в приложении.

## HTTP без установки прокси

```bash
PYTHONPATH=src python3 -m iirpg --host 0.0.0.0 --port 8000 --access-token-file .local/access-token
```

Открывайте `http://ВАШ_ПУБЛИЧНЫЙ_IP:8000/`. Ключ доступа можно ввести в форме
или перенести фрагмент `#room=…&access=…` из старой ссылки.
Нужен входящий TCP 8000 в firewall машины и провайдера.
Запуск на этом порту не требует прав администратора, изменение firewall требует.
По HTTP ключ и переписка передаются без шифрования.

Браузер генерирует UUID через `crypto.randomUUID()`, если он доступен,
иначе использует `crypto.getRandomValues()` с форматом UUIDv4.
Последний API доступен и по HTTP: [документация MDN](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues).
При недоступности браузерного буфера обмена кнопка копирования показывает
ссылку для ручного копирования. Обычные сообщения и броски работают по HTTP.

## HTTPS

Схема: браузер → HTTPS на публичном IP → Caddy → Python `127.0.0.1:8000`.
При выборе HTTPS наружу открываются порты 80/443, а порт Python остаётся локальным.

Let's Encrypt выдаёт публично доверенные сертификаты для IP в профиле
`shortlived`, сроком около шести дней. Caddy автоматически обновляет сертификат.
Профиль и ACME-сервер указаны явно в [deploy/Caddyfile](../deploy/Caddyfile).

Источники: [сертификаты IP в Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/),
[параметр profile в Caddy](https://caddyserver.com/docs/caddyfile/directives/tls#issuers).

## Установка на Ubuntu Linux x86_64

Python-сервер должен работать на `127.0.0.1:8000` с `--access-token-file`.
Установщик проверяет `/health` и отказ API без ключа до открытия доступа.

Из корня репозитория запустите следующую команду, заменив пример адреса
на фактический публичный IPv4 машины:

```bash
sudo bash deploy/install-direct-ip.sh 203.0.113.10
```

Установщик:

- скачивает Caddy 2.11.7 из официального GitHub-релиза и проверяет закреплённую SHA-256;
- устанавливает бинарный файл `/usr/local/bin/iirpg-caddy`;
- создаёт отдельного системного пользователя `iirpg-web` и службу `iirpg-caddy`;
- сохраняет конфигурацию и публичный IP в `/etc/iirpg-caddy/`;
- хранит сертификаты и ключи в `/var/lib/iirpg-caddy/` с доступом для службы;
- добавляет TCP 80 и 443 в UFW, если этот firewall уже активен;
- запускает службу и проверяет HTTPS с доверенным сертификатом.

Порты TCP 80/443 должны быть доступны извне, в том числе через firewall
провайдера. Порт 8000 наружу открывать не нужно. При наличии NAT необходимо
направить 80/443 на эту машину. Проверка установщика подключается локально;
доступность для другого устройства необходимо проверить отдельно.

Требуются права администратора: установка systemd-службы и использование
портов 80/443 недоступны обычному пользователю. Пароль `sudo` вводится только
в собственном терминале, передавать его в чат не нужно.

Python-сервер устанавливается и запускается отдельно; текущая tmux-сессия
продолжает обслуживать ту же базу. Эта установка включает автозапуск только
HTTPS-прокси. После перезагрузки машины нужен также запуск Python-сервера.

## Проверка и переключение

Откройте `https://ВАШ_ПУБЛИЧНЫЙ_IP/` на другом устройстве. Введите прежний ключ
доступа или перенесите фрагмент `#room=…&access=…` из старой ссылки на новый адрес.
Для новой вкладки с новым адресом может понадобиться повторный ввод ключа:
хранилище браузера привязано к адресу сайта.

Проверьте историю и отправку сообщения. В JSON-заглушке можно отправить
предложение броска, принять его в чате и убедиться, что повтор не перебрасывает кости.
Проверьте также, что без ключа API отвечает `401`.

После успешной внешней проверки можно остановить старый туннель:

```bash
tmux -L iirpg send-keys -t tunnel C-c
```

Обновите локальный файл `.local/public-url` на `https://ВАШ_ПУБЛИЧНЫЙ_IP`,
чтобы сохранённый адрес соответствовал новому способу доступа. Секретный ключ
и ссылки с ним остаются только в `.local/`, который исключён из Git.

## Обслуживание

```bash
systemctl status iirpg-caddy.service
sudo journalctl -u iirpg-caddy.service -n 50 --no-pager
sudo systemctl reload iirpg-caddy.service
```

Не удаляйте `/var/lib/iirpg-caddy/`: в нём ACME-аккаунт и сертификаты.
При ошибке получения или обновления сертификата проверьте доступность 80/443
и журнал службы.
