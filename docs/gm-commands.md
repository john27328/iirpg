# Команды ведущего

ИИ формирует только действие и его параметры. Автор, получатель предложения,
идентификаторы очереди и защита от повтора относятся к транспорту.
В JSON-заглушке по умолчанию выбран режим «Команда ведущего».

## Сообщение

```json
{"action": "say", "text": "Перед вами закрытая дверь."}
```

Для обычного сообщения `action` можно опустить:

```json
{"text": "Что будете делать?", "choices": ["Осмотреться", "Постучать"]}
```

## Предложить игроку бросок

```json
{
  "action": "offer_roll",
  "text": "Проверь скрытность, чтобы пройти мимо стражи.",
  "roll": "1d20+5",
  "target": 15
}
```

Игрок получит кнопку «Бросить кости». Предложение само не вызывает генератор.
По умолчанию формат `d20`, условие успеха `>= target`, автор — ведущий `second`,
получатель — игрок `first`. Поле `label` необязательно: например, `"Скрытность"`.
При принятии игроком параметры и видимость наследуются от предложения.

## Бросить сразу от имени ведущего

```json
{"action": "roll", "roll": "1d20+5", "target": 15}
```

Оба варианта броска требуют `roll` и целочисленный `target`.
Для процентной проверки:

```json
{"action": "roll", "system": "percentile", "roll": "1d100", "operator": "<=", "target": 50}
```

Для пула:

```json
{"action": "roll", "system": "pool_d10", "roll": "5d10", "die_target": 6, "target": 3}
```

Здесь нужно хотя бы три кости со значением ≥ 6. `die_operator` по умолчанию `>=`.
Без `die_target` применяется условие на кость из выбранного формата.
Полный каталог форматов доступен в `GET /api/tools/dice`.

## Видимость и проверка полей

Для всех команд необязательное поле `audience`:

- `all` — оба представления, значение по умолчанию;
- `player` — только игрок;
- `gm` — только ведущий.

Предложение игроку допускает `all` или `player`. Видимость распространяется
на предложение, вызов и результат. При `player` ведущий не увидит результат
в своей подписке. Необязательное поле `metadata` сохраняется как контекст.

Неизвестные действия и поля отклоняются. `request_id`, `sender`, `type`, `tool`
и `recipient` в команде не принимаются: это поля полного формата очереди.
Опечатка в имени поля не превращается в молчаливо пропущенный параметр.

## Транспорт и повторы

`POST /api/rooms/{room_id}/gm/commands` получает команду как тело JSON.
Заголовок `Idempotency-Key` содержит UUID операции, который создаёт клиент
или будущий исполнитель ИИ, а не модель. В JSON-заглушке он добавляется автоматически.
`GET /api/gm/commands` возвращает описание формата, JSON Schema и примеры.
Эти API используют тот же ключ доступа, что и остальное приложение.

Повтор отправки неизменённой команды в текущем редакторе использует тот же
служебный ключ. При сетевой ошибке ключ сохраняется. Пробелы и форматирование
JSON не меняют ключ. Для намеренного повторного действия нажмите «Новая отправка»;
тело команды при этом не меняется. Изменённая команда получает новый ключ.

Сервер сохраняет результат и после перезапуска возвращает его по тому же ключу.
Будущий исполнитель должен сохранить ключ до первого HTTP-запроса и использовать
его при всех повторах одной операции. Повтор с изменённым содержимым и старым
ключом возвращает `409`. Новый ключ означает новую операцию.
Клиентский редактор хранит ключ в памяти до смены комнаты или перезагрузки страницы.

В ответе API и в диагностике истории остаются полные события, позволяющие
проверить автора, видимость и связь предложения с результатом. Старый API
`/messages` и режим «Сырой JSON очереди» поддерживают полный формат с явными ID.
Переключение формата сохраняет отдельные черновики обоих режимов.
