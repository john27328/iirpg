# Готовые герои и создание через чат

В меню «Сеансы» новая игра включает выбор готового персонажа. Изначально
доступны Радан (воин), Лира (плут) и Эрин (маг) первого уровня. Карточки
показывают класс, перк, ОЗ и стартовое снаряжение. Любого готового героя
можно удалить; удаление требует подтверждения и не затрагивает персонажей
в начатых играх. Удалённые стартовые герои не появляются снова при перезапуске.

«Создать персонажа» открывает карточку и чат помощника рядом.
Карточка открывается в отдельном окне. На широком экране помощник расположен
рядом, на телефоне доступны вкладки «Карточка» и «Помощник ИИ».
Карточку можно заполнить вручную без ключа ИИ и без расходования квоты:
имя, класс, общий перк, описание, принципы и табу. Кнопка «Проверить»
сохраняет черновик и показывает рассчитанные характеристики, ОЗ, броню,
Восприятие, скорость и стартовое снаряжение.

Помощник использует обычный чат приложения. Можно начать
с «Я не умею, помоги выбрать» или описать желаемый образ. Помощник объясняет
варианты, предлагает короткие ответы и учитывает следующие уточнения.
Ручные поля передаются помощнику как текущий выбор, а советы без изменения
выборов не создают дубликат уже сохранённого героя. При закрытии формы её
изменения сохраняются как черновик. История и текущий выбор хранятся на сервере; разговор можно продолжить
после перезагрузки через «Продолжить создание».

Когда выбраны имя, класс и перк, в ленте появляется карточка с настоящими
параметрами и кнопкой «Сохранить героя». Сохранение добавляет его в готовые
и выбирает для новой игры. Старые карточки после уточнения нельзя сохранить.
Принципы и табу необязательны и не дают числовых бонусов.
Модель не назначает числовые бонусы, ячейки и предметы: движок собирает героя
из `progression_pf2e.json` и проверяет снаряжение общими правилами инвентаря.
Доступный набор ограничен тремя классами первого уровня, человеком с
универсальным наследием и двумя общими перками; полный конструктор пока
не реализован. [Поддерживаемые механики](classes-and-magic.md).

В новой игре шаблон копируется с новыми идентификаторами персонажа и вещей.
Раны, потраченные ячейки, найденные предметы и состояние приключения относятся
только к этой копии. Сохранение и загрузка игры не откатывают библиотеку
готовых героев и разговоры создания.

## Интерфейс и протокол

`web/chat.js` содержит прежний интерфейс чата: ленту, ввод, варианты ответа,
карточки костей, временное отображение отправленного сообщения и статус
ожидания. Игра, создание героя и обсуждение боя используют этот компонент
с разными транспортами. Во время ответа ИИ можно набирать следующий текст.

- `GET /api/characters`: готовые герои и последние 20 разговоров создания.
- `POST /api/characters`, `action=new_draft`: новая карточка с разговором, ответ `draft_id`.
- `POST /api/characters`, `{action:"update_draft",id,revision,proposal}`: ручное заполнение карточки без ИИ.
  `proposal`: `name`, `class_id`, `general_feat`, `description`, необязательные `edicts`, `anathema`.
  Сырые характеристики, здоровье, уровень и новые неподдерживаемые варианты отклоняются.
- `GET /api/characters/drafts/{id}`: текущий выбор и ревизия.
- `POST /api/characters/drafts/{id}`, `{revision,text}`: сообщение помощнику.
- `POST /api/characters`, `{action:"save",id,revision}`: сохранить готового героя.
- `POST /api/characters`, `{action:"delete",id}`: удалить шаблон героя.
- `POST /api/games`, `action=create`: дополнительно принимает `hero_id`.

POST-запросы используют `Idempotency-Key`. Повторы не создают дубли и не
отправляют запрос модели снова. Все API защищены общим ключом доступа.
Реплики создания используют существующую очередь комнаты и API сообщений;
такая комната не добавляется в меню игровых сеансов.

Вызов модели происходит вне транзакции SQLite. Ответ повторно проверяется
по ревизии. Используются текущая бесплатная модель, нулевая предельная цена,
общий дневной лимит и журнал `ai_requests` с ролью `character_creator`.
Неудачный ответ не меняет выбор, отправленная реплика остаётся в истории.

Проверки без сети: `tests/test_hero_library.py`, HTTP-проверки в `test_server.py`.
Отдельный добровольный прогон бесплатной модели:
`PYTHONPATH=src python3 release_tests/live_character_creation.py --live`.
Он использует отдельную тестовую базу; отчёт и SQLite сохраняются
в `.local/creator-live-*.json` и `.sqlite3`. Пользовательские игры и библиотека
не затрагиваются.


## Лист в начатой игре

Лист игрового персонажа предназначен для просмотра. В нём нет редактирования
характеристик, здоровья, уровня и стартовой сборки. В игровой карточке также
нет ручного изменения данных NPC. API реестра отклоняет создание, удаление,
`update_character` и `configure_build` в зарегистрированной игре даже для
владельца стенда. Изменения инвентаря через предусмотренные действия остаются
доступны; урон, лечение, покупки и расход дневных ресурсов записывает движок.
Неигровой реестр сохраняет возможности редактирования для тестовых стендов.

`GET /api/rooms/{id}/roster` возвращает `is_game`, по которому интерфейс выбирает
режим просмотра. Запрет API проверяется по базе, а не по этому клиентскому флагу.
Повышение уровня и опыт в этот конструктор не входят. Характеристики текущих
сборок фиксированы выбранным классом; свободное распределение повышений,
полный список происхождений и предысторий пока не поддерживаются.

## Проверки

Обычные тесты проверяют ручную карточку без ИИ, частичный черновик, валидацию,
конкурентные изменения, сохранение убеждений, отсутствие дубликатов при совете
и запрет изменения игрового героя через API владельца и приглашённого игрока.
Существующие проверки урона, лечения, предметов, магии и перезапуска проходят
через игровые механизмы. Подготовка искусственных ран и навыков в тестах теперь
выполняется напрямую в тестовой базе, без пользовательского редактора статов.

Живой прогон бесплатной `nemotron-3.5-super-vl:free`: четыре запроса. Помощник
объяснил перк, не принял силу 99, сменил только класс, затем только имя,
сохранив остальные поля. Сохранённый герой начал отдельную игру, запрос
владельца на изменение его силы получил HTTP 403.

Браузерная проверка с заглушкой только на границе ИИ проходит создание карточки,
подсказку, сохранение, новую игру, лист для просмотра, запрет API, мобильную
раскладку и сохранение черновика при закрытии. Она отдельно запускается с Node.js
и Playwright; эти инструменты не нужны для работы игры и обычных Python-тестов:

```bash
npm install --prefix .local/ui-check playwright
.local/ui-check/node_modules/.bin/playwright install --with-deps chromium
PYTHONPATH=src python3 release_tests/browser_character_creation.py --playwright-module .local/ui-check/node_modules/playwright/index.mjs
```

Итоговая проверка изменения: 360 обычных тестов, 14 проверок выпуска и отдельный
браузерный проход на Chromium; все проходят.

## Создание под личный образ

Отдельный прогон проверяет честную плутовку-спасательницу, мирного мага,
воина-дипломата и запрос эльфа-друида с превращением и лечением. Проверяется,
что помощник не выбирает перк до согласия, не заменяет неподдержанный образ
без разрешения, сохраняет остальные поля при изменении одного и не добавляет
описанием несуществующие бонусы или заклинания.

```bash
PYTHONPATH=src python3 release_tests/live_character_creation.py --live --case preferences --model nvidia/nemotron-3.5-super-vl:free --max-requests 25
```

Первый проход выявил пробел интеграции: личное описание и убеждения сохранялись
в карточке, но не передавались игровому ведущему. Теперь `hero_identity`
передаёт описание, происхождение, класс, предысторию, принципы и табу текущего
героя планировщику и рассказчику. Это данные об образе; они не дают бонусов и
не разрешают принимать решения за игрока. NPC не получают такие сведения
как автоматически известные им факты.

Повтор на бесплатной модели: 3 сценария, 40 проверок, 9 запросов, без ошибок;
указанная провайдером стоимость 0. После создания ведущий без напоминания
описания вспомнил дипломата Льва, его привычку договариваться и табу на
унижение слабых. Проверки сохранения выбора дополнены обычной регрессией
передачи образа обоим игровым AI-контекстам; всего проходят 361 обычный тест
и 14 проверок выпуска.

Настройка образа пока не равна произвольной механической сборке. Воин с другими
характеристиками или посохом вместо штатного меча и щита на этапе создания
не поддержан; эльф-друид также недоступен. В проверке помощник объяснил это
и предложил варианты, не выдавая недоступные способности за готовый результат.


## Мобильный интерфейс

Создание героя не требует прокрутки списка готовых персонажей: кнопка находится
рядом с формой новой игры и открывает отдельный диалог. На ширине до 850 px
форма и чат переключаются вкладками; при расширении окна снова видны оба.
Кнопки проверки и сохранения доступны внизу карточки. Закрытие и Escape
сохраняют ручной черновик; подтверждённое сохранение героя остаётся отдельной
кнопкой. Параметры и длинное описание сборки раскрываются по запросу.

На телефоне основные кнопки имеют область касания не меньше 44 px, поля —
шрифт 16 px; нижняя навигация открывает чат, персонажа, бой и сеансы. Учтены
безопасные отступы экрана. Высота диалога и чата следует за видимой областью;
при небольшой высоте шапка помощника упрощается. Тактический чат использует
компактную кнопку отправки, а длинные подписи переносятся. Учебная подготовка
боя доступна только при явном режиме разработчика.

Дополнительный прогон Chromium без внешнего ИИ:

```bash
PYTHONPATH=src python3 release_tests/browser_character_creation.py --check mobile --playwright-module .local/ui-check/node_modules/playwright/index.mjs
```

Проверены ширины 320, 390, 430, 768 и 1280 px: меню, создание, переключение
вкладок с клавиатуры, укороченная высота 440 px, сохранение, просмотр листа без
редактирования статов, изменение расположения предмета, отправка в игровой
чат. Отдельно проверены переход через границу мобильной раскладки, сохранение
черновика по Escape и открытие тактической страницы на ширинах 320 и 390 px.
Проверяются размеры кнопок, горизонтальное переполнение и ошибки JavaScript.
Это браузерная эмуляция размеров и касания, а не проверка на физических iOS- и
Android-устройствах; появление системной клавиатуры заменено уменьшением высоты.
