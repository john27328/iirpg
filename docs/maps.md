# Карты для генерации ИИ

Формат `iirpg-map-v1` — чистый JSON. Карта задаёт геометрию, зоны и объекты,
а персонажи добавляются из реестра комнаты. Две авторские заготовки:

- `src/iirpg/rules/maps/tavern.json` — таверна со столом и стойкой;
- `src/iirpg/rules/maps/forest_camp.json` — лесной лагерь с зарослями и валуном.

`GET /api/maps` возвращает обе заготовки, `GET /api/maps/schema` — JSON Schema
2020-12. Оба API используют общий ключ доступа. Схема также лежит в
`src/iirpg/rules/map_schema.json`. В игровом интерфейсе можно выбрать заготовку,
скачать её JSON, загрузить файл или вставить результат генерации ИИ.
Приложение само не обращается к внешнему ИИ.

## Минимальный документ

```json
{
  "schema_version": 1,
  "id": "small_room",
  "name": "Маленькая комната",
  "description": "Пустая комната для начала приключения.",
  "rows": ["#####", "#...#", "#...#", "#####"],
  "zones": [{"id": "room", "name": "Комната", "cells": [[1,1],[2,1],[3,1],[1,2],[2,2],[3,2]]}],
  "objects": [],
  "spawn": [1,1]
}
```

Координаты `[x,y]` считаются с нуля от левого верхнего угла. `#` — стена,
`.` — обычный пол, `~` — трудная местность. Клетка соответствует 5 футам.
Каждая проходимая клетка должна входить ровно в одну зону; стены не входят.
Связи зон вычисляются сервером по соседству клеток. Объекты задаются так:

```json
{"id":"table","name":"Стол","position":[2,2],"posture":"upright","provides_cover":false,"blocks_movement":true}
```

`posture`: `upright`, `fixed`, `overturned`. ID карты, зон и объектов —
латинские ключи до 40 символов. В пределах своего списка ID уникальны.
Объекты не пересекаются, не занимают стены и точку появления. Все свободные
клетки должны быть достижимы от `spawn` с учётом блокирующих объектов.
Максимум: 40×30 клеток, 30 зон, 100 объектов. Сервер проверяет также ограничения,
которые JSON Schema не выражает: одинаковую длину строк, ссылки на клетки,
разбиение зон, уникальность ID и связность. Ошибка не изменяет сцену.

## Задание для ИИ

> Сгенерируй один JSON-документ карты IIRPG map v1 без Markdown и пояснений.
> Используй приложенную JSON Schema и tavern.json либо forest_camp.json как
> пример. Размер не больше 20×15. Разрешены только #, . и ~. Каждую клетку пола
> и трудной местности включи в cells ровно одной зоны. Координаты [x,y], начало
> слева сверху, индексация с нуля. spawn расположен на свободной клетке.
> У всех зон и объектов уникальные короткие латинские id. Объекты стоят на полу,
> не перекрывают spawn и друг друга. Все свободные клетки достижимы от spawn
> при движении по четырём направлениям. Не добавляй персонажей, скрипты, HTML,
> файлы изображений или новые поля. Названия и описание напиши по-русски.
> Локация: [описание желаемой локации].

После генерации вставьте JSON в панели карты: сервер окончательно проверит его.

## Действия

Загрузка: `POST /api/rooms/{room}/scene`, UUID `Idempotency-Key` и тело:

```json
{"action":"load_map","revision":4,"parameters":{"template_id":"tavern"}}
```

Либо `parameters: {"map": DOCUMENT}` для собственного JSON. Загрузка заменяет
геометрию и объекты, переносит существующих участников на spawn и снимает
укрытия. Ожидающие намерения получают статус `cancelled`; прошлый журнал
и решённые намерения сохраняются. Листы персонажей не меняются.

Перемещение кликом отправляет:

```json
{"action":"move_cell","revision":5,"actor_id":"UUID","parameters":{"position":[3,2]}}
```

Сервер находит кратчайший доступный путь и проверяет Скорость из листа:
обычная клетка стоит 5 футов, трудная — 10. Стены и блокирующие объекты непроходимы.
Перемещение обновляет координаты и зону, снимает укрытие. Для действий с объектом
нужно находиться в той же зоне и на соседней ортогональной клетке.
Клик на объект выбирает его целью, не выполняя проверку автоматически.

Это пространственный прототип: движение пока только по четырём направлениям,
без диагоналей PF2e, высоты, размеров существ, тумана войны и линий видимости.
Вне боя персонажи могут находиться в одной клетке. В бою активные участники
занимают клетки и блокируют проход, включая союзников (упрощение прототипа).
Вне боя перемещение свободное; в новом учебном бою оно расходует действие (см. ниже).
На карте старое перемещение между зонами заменено выбором конкретной клетки.
Все изменения продолжают попадать в `scene.action`, повторы и конфликты
обрабатываются существующим механизмом ревизий и квитанций.

## Учебный бой на карте

При начале нового боя на загруженной карте герой использует свою клетку сцены;
противник появляется на доступной свободной клетке. Его ID `training:...`
отличает учебного участника от сохранённых NPC. Перемещение расходует одно
действие перемещения после выбора клетки и кнопки «Переместиться» на `/battle`;
клик по противнику выбирает цель для кнопки «Удар». Досягаемость — соседняя
ортогональная клетка. Стены, объекты, трудная местность и Скорость учитываются.
Соперник сам подходит по доступному пути и атакует оставшимися действиями.

`POST /combat`: `action: move` с `position: [x,y]`; `action: take_cover` с
`target_id` объекта. Укрытие даёт бонус к КБ; из укрытия и щита берётся больший
circumstance-бонус. Атака и перемещение снимают укрытие. Учебные ОЗ остаются
отдельными от листа. `combat.action` содержит позиции и действия до/после.
Сцена и бой сохраняются в одной SQLite-транзакции, оба повышают свои ревизии.
Во время боя перемещение через свободные действия сцены и замена карты
заблокированы; текстовые намерения сохранять можно, их разрешение отложено.

Учебный бой поддерживает героя и группу до трёх противников с отдельными
ходами и выбором цели. Ограничения: ортогональная сетка, без диагоналей,
высоты, направленного расчёта линий укрытия, заклинаний и реакций. Бонус
занятого укрытия считается против всех атак. Старый бой без позиций можно
закончить прежними кнопками; связь с картой появляется при следующем старте.
